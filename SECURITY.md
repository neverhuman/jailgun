# Security reports

Do not put credentials, browser profiles, private prompts, or exploitable account
access details in a public issue. Use GitHub's private vulnerability reporting
for this repository when it is available. If the private reporting option is
not available, open a public issue requesting a private reporting channel without
disclosing the vulnerability details.

Include the affected version/commit, a synthetic reproduction, expected versus
actual behavior, and the access level needed to trigger the issue. Never attach
real authentication material. No response-time or supported-release guarantee
has been established for the v0.2.0 work in progress.
